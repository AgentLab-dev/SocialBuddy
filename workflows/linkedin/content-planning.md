# Workflow: content planning

## Purpose

Produce a **time-boxed plan** of topics and draft outlines grounded in skills + eligible profile facts — not a calendar of auto-posts.

## Inputs

- Validated public facts (from profile validation).
- Domain skills to compose (dbt, Snowflake, AI, …).
- Cadence constraint (e.g. 2 posts/week — operator-set).
- Forbidden topics (legal, employer comms).

## Procedure

1. **Pillars** (3–5): each pillar maps to a skill id and a claim family the operator can defend (e.g. “incremental failure modes,” “RBAC two-layer,” “evals before prompts”).
2. **Backlog:** for each item — working title, claim, evidence record ids, channel (`post` / `article` / `comment-thread`), risk (`low` if all evidence public).
3. **Sequence:** alternate teaching vs case-study-shaped posts; do not schedule more than one “I am hiring / I am looking” per window unless the operator asked.
4. **Draft outline** with `phd-writing` procedure; first line test; citation list (real locators only).
5. **Queue** drafts as artifacts. Status: `outline` → `draft` → `awaiting_approval` → (human) → `approved` / `rejected`.
6. **Never** move to `sent` without approval-gate.

## Quality bar

A plan that needs invented metrics is incomplete. Drop the item.
